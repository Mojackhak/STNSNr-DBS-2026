# Publication code extraction

## Scope and source

This branch extracts the code needed by the STN-SNr manuscript figures from
MyLFP commit `986358b112dcd2d032a55a425702049aa3a6c5a8`. The source branch is
`main`; the publication working branch is `nn2026`.

The figure inventory comes from the 38 YAML files in the manuscript's
`figure0930` directory: eight main figures, four Extended Data figures and
26 Supplementary figures, containing 304 panel/provenance records. A record
may describe a composite or an unlettered schematic rather than one plot.

## Extraction rules

1. Map every panel to its recorded inputs, plotting/statistical entrypoints,
   and upstream processing. Distinguish output-name matches from verified
   historical execution; neither a filename nor a current script establishes
   that the exact publication output was generated by this commit.
2. Retain required Python imports, R source files, MATLAB helpers, settings,
   relevant tests and documentation. Keep the established module layout.
3. Use `MYLFP_PROJECT_ROOT` for the analysis data tree and `MYLFP_REPO_ROOT`
   for R/MATLAB source lookup. Python scripts resolve repository imports from
   their own location. Example subject identifiers contain no participant names.
4. Preserve numerical algorithms, statistical models, thresholds, correction
   rules and figure encodings. This extraction is not a statistical reanalysis.
5. Preserve the source figure directory and the `main` reference. Leave local
   `tmp/` artifacts untouched and exclude them from the publication inventory.
6. Use synthetic demonstration inputs. Record absent analysis code, restricted
   data and manual figure assembly explicitly; do not invent a reproduction.

## Dependency and data boundaries

Python, R and MATLAB dependencies are documented separately. Lead-DBS,
Wave_clus, anatomical atlases and Illustrator are external software/assets;
they are not copied into this repository. The existing MIT license applies
to the included original code, not automatically to external assets.

The historical YAML roots `/Volumes/VAL/STNSNr`,
`/Volumes/Data/STNSNr2026` and the original local research directory are
represented by `${MYLFP_PROJECT_ROOT}` in portable provenance copies. This
normalization preserves relative filenames and does not assert that the
different data trees contain identical numerical results.

## Validation scope

The extraction found legacy `plugin.*` imports in several retained entrypoints
although the source commit stores those modules under `plugin/default/`.
Those imports are updated to the existing module locations. Interactive MER
and LFP example paths are replaced with explicit environment inputs. The
gait-feature combined-fit module is a helper; its calling single-feature
entrypoint is retained as the executable reproduction step.

The active-contact workflow imports a sibling `programming_contacts.py`; that
file is retained. Two legacy LFP test files import an absent, unrelated `anat`
package and are excluded from this publication subset. They are not rewritten
as tests of the current anatomy implementation.

The inherited pose environment recipe describes a different DeepLabCut-based
installation and does not specify the selected MMPose/Ultralytics workflow.
It is excluded; the actual external pose dependencies are documented without
claiming a tested installation or inventing their historical versions.

Python scripts use required `MYLFP_PROJECT_ROOT` and, where needed,
`MYLFP_REPO_ROOT` environment variables. Interactive subject selection uses
`MYLFP_SUBJECT`. The FoG video illustration requires its original annotated
recording through `MYLFP_FOG_RAW`; no patient-named default is distributed.

Validation will cover the panel inventory, retained dependency paths, syntax,
the directly relevant existing tests, and small statistical/plotting demos.
No complete cohort pipeline, model refit, cache invalidation, or manuscript
figure replacement is part of this extraction. Installation and demo timing
must be reported as measured or explicitly unmeasured.

This is a source snapshot for review. Public hosting, persistent identifiers,
and any further licensing or data-access decisions are separate publication
steps. Repository history is inherited from MyLFP; a source-only archive would
contain the selected current files, not the full Git history.
