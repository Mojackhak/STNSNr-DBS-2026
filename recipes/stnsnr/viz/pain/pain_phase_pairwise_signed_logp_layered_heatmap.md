# Pain Phase Pairwise Signed-LogP Layered Heatmaps

## Purpose

This visualization renders raw pain `Phase` pairwise signed-logP heatmaps from
the intermediate table generated by:

```text
recipes/stnsnr/stats/pain/pain_phase_pairwise_signed_logp.py
```

## Input

The renderer reads:

```text
${MYLFP_PROJECT_ROOT}/summary/stats/pain/corr/phase_pairwise/pain_phase_pairwise_signed_logp_values.csv
```

The input table must use raw `rlmer_model` sources and source contrasts
`BL - ONS`, `BL - SUS`, `BL - OFS`, `BL - PST`, `ONS - SUS`, `ONS - OFS`,
`ONS - PST`, `SUS - OFS`, `SUS - PST`, and `OFS - PST`.

## Figure Layout

All heatmaps use:

- ten layered panels ordered `BL vs ONS`, `BL vs SUS`, `BL vs OFS`,
  `BL vs PST`, `ONS vs SUS`, `ONS vs OFS`, `ONS vs PST`, `SUS vs OFS`,
  `SUS vs PST`, `OFS vs PST`;
- `3.0 x 3.0 mm` cells;
- black solid grid lines;
- display values clipped to `[-3, 3]`;
- the shared `visualdf.plot_well_heatmap_grid_df` backend.

Frequency bands are ordered as:

```text
Delta, Theta, Alpha, Beta_low, Beta_high, Gamma
```

The renderer creates original and transposed heatmaps for:

- `SNr`
- `STN`
- `SNr-/→STN`
- `Params`

The intermediate CSV may contain the `Aperiodic power` local metric, but this
metric is omitted from all rendered heatmaps.

It also creates one combined summary heatmap for `SNr`, `STN`, and
`SNr-/→STN`. Params are not included in the combined summary heatmap.

The combined summary uses right strips ordered by the ten phase comparisons;
top strips ordered `SNr`, `STN`, `SNr-/→STN`; y-axis bands; and x-axis metric
labels.

## Encoding

The shared colorbar is labeled:

```text
Signed (b-a) -log10(p_Tukey) (a vs b)
```

For a panel labeled `a vs b`, positive values mean `b > a`.
Significance stars come from `p_tukey`.

## Outputs

Heatmap files are written to:

```text
${MYLFP_PROJECT_ROOT}/summary/stats/pain/corr/phase_pairwise
```

Generated heatmap basenames:

- `pain_phase_pairwise_snr_local_signed_logp_layered_heatmap`
- `pain_phase_pairwise_stn_local_signed_logp_layered_heatmap`
- `pain_phase_pairwise_connectivity_signed_logp_layered_heatmap`
- `pain_phase_pairwise_params_signed_logp_layered_heatmap`
- `pain_phase_pairwise_snr_local_signed_logp_freq_by_param_layered_heatmap`
- `pain_phase_pairwise_stn_local_signed_logp_freq_by_param_layered_heatmap`
- `pain_phase_pairwise_connectivity_signed_logp_freq_by_param_layered_heatmap`
- `pain_phase_pairwise_params_signed_logp_transposed_layered_heatmap`
- `pain_phase_pairwise_summary_freq_by_param_signed_logp_layered_heatmap`

Each basename is exported as PDF and PNG.

## Local Metric Composition

The local renderer uses the signed-logP CSV to compose SNr and STN panels.
Exponent and Offset are omitted from every local composition because their
traces and phase-comparison figures already show those features. Each row contains:

- an SNr panel and an STN panel, each with six metric rows and six frequency
  columns, using the original (not transposed) group matrices;
- a full-height right comparison strip.

All cells measure `3 x 3 mm`. Local panels measure `18 x 18 mm`.
SNr and STN have top strips. Metric labels appear at the left of every row, and
x-axis labels appear only on the final row of each exported figure.

The composition reuses the existing matrix builders and `visualdf` panel,
strip, and colorbar helpers. Removing the parameter column changes only the
figure width; local cell size, type sizes, and comparison spacing are retained.
Colors, Tukey stars, and the shared `[-3, 3]` scale retain the original encoding.

Three compositions are exported, each as a vector PDF and a 600 dpi PNG:

| Basename | Comparisons in display order |
| --- | --- |
| `pain_phase_pairwise_local_signed_logp_layered_heatmap` | All ten comparisons |
| `pain_phase_pairwise_local_signed_logp_layered_heatmap_bl_comparisons` | BL vs ONS, BL vs SUS, BL vs OFS, BL vs PST |
| `pain_phase_pairwise_local_signed_logp_layered_heatmap_non_bl_comparisons` | ONS vs SUS, ONS vs OFS, ONS vs PST, SUS vs OFS, SUS vs PST, OFS vs PST |

The dedicated command reads the explicitly supplied existing CSV once and
writes only these six files beside it. It does not rerun statistics or the
other heatmap exports. The original no-argument workflow remains available.
The reference PDF and the original summary exports are not output targets.

Changes to local-metric CSV values affect the corresponding plotted cells.
Exponent/Offset values are not consumed by the local composition. Comparison
selection and layout affect only the requested composition;
there is no cache or invalidation mechanism and no upstream recomputation.

Validation checks comparison coverage, rendered matrix orientation, the sign
and Tukey stars against the input CSV, physical cell sizes, parameter exclusion,
and consistent color limits. Render all three PDFs and inspect labels, strips,
and colorbars for clipping or overlap.

## Connectivity Comparison Subsets

The connectivity subset command exports two figures using the same layout as
`pain_phase_pairwise_connectivity_signed_logp_layered_heatmap.pdf`. Each panel
has five metric rows (coherence, wPLI, ciPLV, TRGC, PSI) and six frequency
columns. It retains the original transformed metric labels, `3 x 3 mm` cells,
SNr-/->STN top strip, right comparison strips, Tukey stars, and shared
`[-3, 3]` color limits. Each subset has its own colorbar and bottom frequency
labels.

The two subsets share the comparison definitions used by the local
figures. They are exported beside the explicitly supplied signed-logP CSV as
PDF and 600 dpi PNG:

- `pain_phase_pairwise_connectivity_signed_logp_layered_heatmap_bl_comparisons`:
  BL vs ONS, BL vs SUS, BL vs OFS, BL vs PST.
- `pain_phase_pairwise_connectivity_signed_logp_layered_heatmap_non_bl_comparisons`:
  ONS vs SUS, ONS vs OFS, ONS vs PST, SUS vs OFS, SUS vs PST, OFS vs PST.

The group renderer accepts a comparison sequence and an output specification;
its default behavior still renders all ten comparisons. The dedicated subset
workflow reads the CSV once and renders only the two connectivity subsets.
It does not regenerate the complete connectivity figure, local/parameter
figures, or statistics. CSV values and display selections affect only these
rendered outputs; no cache or invalidation mechanism is introduced. The
existing complete-CSV validation remains the input contract.

Verification covers all 300 connectivity cells and their significance stars,
subset coverage and order, matrix orientation, physical cell dimensions, and
the rendered PDFs' labels and colorbars.

## Run Command

Use the MyLFP default Conda environment:

```bash
conda run -n LFP python recipes/stnsnr/viz/pain/pain_phase_pairwise_signed_logp_layered_heatmap.py
```

To generate only the three local compositions from the mounted data:

```bash
conda run -n LFP python recipes/stnsnr/viz/pain/pain_phase_pairwise_signed_logp_layered_heatmap.py \
  --local-input ${MYLFP_PROJECT_ROOT}/summary/stats/pain/corr/phase_pairwise/pain_phase_pairwise_signed_logp_values.csv
```

To generate only the two connectivity subsets:

```bash
conda run -n LFP python recipes/stnsnr/viz/pain/pain_phase_pairwise_signed_logp_layered_heatmap.py \
  --connectivity-input ${MYLFP_PROJECT_ROOT}/summary/stats/pain/corr/phase_pairwise/pain_phase_pairwise_signed_logp_values.csv
```

The two dedicated input options are mutually exclusive.
